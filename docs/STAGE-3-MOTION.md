# NEXT ROBOTICS 阶段三：动作系统验收

验收日期：2026-11-16。依据 ROLE.md / MASTER_PROMPT.md 第二十一章阶段三及第五、六、八章动作与运动学要求。本轮集中阶段三，阶段四至九继续按计划实施。

## 1. 本阶段完成内容

沿用两种原创机械模型和唯一 `SimulationAdapter`，将全部运动求解收敛到统一快照。3D 模型、控制面板、动作库、机器人目录和遥测读取同一状态与关节目录，不再在渲染层自行生成手臂动作。没有新增运行时依赖。

| 机器人 | 动作与控制轴 |
| --- | --- |
| 四足机器狗 | 自然待机、站立、行走、后退、对角小跑、奔跑、左转、右转、坐下、跳跃、下蹲、台阶步态、动态平衡、身体晃动，共 14 动作、12 受限轴 |
| 人形机器人 | 自然待机、站立、行走、后退、奔跑、左转、右转、挥手、举起双臂、下蹲、弯腰、抓取演示、搬运姿态、握手、指向、抓握、张开手掌，共 17 动作、45 受限轴 |

工作台与实验室提供「动作 / 关节 / 末端 IK」入口；暂停、急停、重置、相机、全屏、画质、部件悬停和历史页面能力继续保留。本机生产预览为 [http://127.0.0.1:4173/](http://127.0.0.1:4173/)，开发服务为 5174。

## 3. 新增功能与修复

- 四拍行走具有 76% 支撑相，每次最多一足摆动；小跑对角同步，奔跑采用前后足组交替。人形双足交替并协调摆臂，奔跑缩短支撑相。0 m/s 停止迈步，后退使用反向轨迹。
- 跳跃包含蓄力、起跳、腾空收腿、落地缓冲和恢复。坐下/下蹲改变重心；机身俯仰/侧倾由腿部 IK 补偿足端高度。
- 人形腰/颈/双臂/腕/28 个指节进入同一姿态数组。张开、抓握和指向具有不同的真实指节角度；每根手指的 3/3/3/3/2 节独立受控。
- 独立关节滑块显示目标角度、当前角度和限位，单轴控制不改其他关节目标。四足每只足端支持髋坐标系 X/Y 定位，人形双掌支持肩坐标系 X/Y/Z 定位，超出工作空间明确拒绝并保留已确认目标。
- 腿部/足端实验抬高机身留出活动空间；手臂、手腕与手指控制保持当前高度。恢复站姿统一回到中立支撑姿态。
- 支持 0.25–2× 倍率、循环/单次、停止；静态姿态保持，单次动态动作结束后回站立。动作切换与渲染插值先混合实际足端坐标再解 IK，避免直接插值腿角造成脚掌下沉。
- 每机独立记录最多 20 秒实际姿态及朝向，支持结束、回放和清除。暂停冻结时钟和记录，急停结束记录并冻结当前姿态，重置清除记录且保留急停锁定。含转向的记录在进入/循环边界平滑衔接朝向。
- 实测修复：托举动作肘轴方向错误、旧遥测把新增关节误标为腿、目录在 IK 模式仍显示旧动作、技能编号 010，以及短屏急停不在首屏。人形肘轴与 IK 统一为向前屈曲，托举上臂自然下垂、前臂前伸。

已核对安装的 Three.js 0.187.0 `Euler` / `Quaternion` / `MathUtils` 源码和官方 [Euler](https://github.com/mrdoob/three.js/blob/r187/docs/pages/Euler.html)、[MathUtils](https://github.com/mrdoob/three.js/blob/r187/docs/pages/MathUtils.html) 文档；保留当前 XYZ 旋转顺序，角度统一为弧度。未新增物理引擎或动画依赖。

## 5. 未解决的问题与边界

- 阶段三没有已知阻塞问题。真实手机、Safari/Firefox、低端 GPU、长时间压力和用户持续拖动所有关节组合尚未执行专项验收。
- 当前为本地原地运动学仿真，不连接真实设备，无场景平移、动力学平衡、刚体碰撞、足底力反馈或全身自碰撞求解。限位不等同于所有手动关节组合都不会自交。
- 抓取、搬运和台阶步态完成动作演示；真实场景物体的拾取/附着/搬移及上下阶梯任务属于阶段七。动态平衡展示机身姿态与 IK 补偿，不代表真实力学稳定性。
- 模型继续使用项目原创程序化机械结构，无外部模型、贴图、字体、账号或 API 依赖；第三方库保留各自许可证。
- 当前目录无 Git 元数据，本轮未提交、推送或远端部署。开发/生产预览均为本机服务。
